# 帮我回

言外把 Jev 情绪判断和 LLM 回复建议分开。桌面设置页顶部切换「情绪判断 / 回复建议 / 关于言外」，两套地址、Key、模型、检测状态独立。只配置回复模型也可以使用「帮我回」。

## 配置

1. 在「回复建议」选择豆包、小米 MiMo、DeepSeek、OpenAI GPT、智谱 GLM 或 Kimi。地址自动匹配，可通过页面按钮前往官方平台获取 API Key；代理、其他区域或套餐地址请选择「自定义」。
2. 填入对应 Key，点击「获取模型列表」。在模型下拉框选择，输入名称可筛选，也可直接填模型 ID。获取列表只发送 Key，不发送聊天内容，不要求先填模型或开启手动生成许可。
3. 列表只代表接口返回的候选，不保证模型支持当前回复接口或账户有权限。豆包、GLM 可另选官方文档参考模型，明确标注目录来源与日期，不冒充账户可用列表；无法列举时仍可手动填写。豆包也支持填写 `ep-` 推理接入点。
4. 阅读说明，开启「允许手动生成回复建议」，保存。未开启时聊天入口会引导配置，不上传聊天。
5. 「保存并检测回复」使用示例聊天和通用接话资料生成一次真实回复，验证接口及输出格式，预览按条编号。不会读取微信聊天；该调用使用自己的服务商额度。检测和获取列表时锁定表单，离开设置页销毁 Activity 会取消请求。

供应商分别保存地址、Key 和模型；切换后需保存当前供应商才生效。同一页面内切换保留未保存输入，关闭页面则放弃未保存修改。升级会识别原有官方地址，其他地址保留为自定义；第一次切换保存前保留旧账户配置。只把当前生效配置同步到微信，不共享其他供应商的 Key。

根地址自动补 `/v1/chat/completions`，已有路径的 Base URL 补 `/chat/completions`，完整地址不重复追加。地址不允许包含账号密码、查询参数、锚点。使用 Bearer Key、`model`、`messages` 和 `stream=false`，不要求服务商支持专用工具调用或 `response_format`。系统指令要求 JSON 回复；空结果、拒绝、输出被截断、无法解析、HTTP/业务错误均显示失败，不把残缺输出当成可发送建议。

## 聊天流程

- 入口收进微信聊天「＋」展开面板，顶部增加 48dp 图标入口；不再在聊天列表上方悬浮，也不再增加消息列表底部留白。保留原生照片、拍摄等项目及监听器，离开恢复面板结构。首次需要用户手机验证该版本 AppPanel 的布局适配；布局未匹配时不注入，可长按标题「分析」选择「帮我回 / 上次建议」，或长按对方文字进入。
- 点「帮我回」只展开抽屉，首次打开也不自动生成。先选对方身份，再填写可选补充想法，点击「生成回复」。已有成功结果时直接展示，不重新调用模型，也不要求先滚回底部。生成/重新生成/更简短/更新才重新收集当前聊天并查历史。
- 身份包含未指定、暗恋对象、暧昧对象、恋人、朋友、长辈、弟弟妹妹、其他家人、同事和其他关系。菜单选择不会生成；亲属年龄、性别和对方感情不从标签推断。群聊身份只用于本轮明确回应的对象，不套到所有成员。
- 分条回复按语意和停顿组织，通常 1–3 条、最多 6 条，总长不超过 8,000 字符。可以先短回应再说具体内容，一条足够时不强拆；“OK”“嗯好”“昂”等根据用户实际口吻与关系使用，不机械添加。它们是依次发送的一组消息，不是多个备选答案。
- 抽屉顶部依次显示身份、紧凑输入框与生成操作；回复逐条显示序号和选中状态，理由按需展开。底部固定「复制这条 / 填入第 N 条」，每次只使用所选的一条。默认回应当前整段聊天；长按对方文字仅传递重点消息 ID，不启用微信引用回复。
- 点击参考范围可以查看这一次实际带入的消息、说话人及时间。
- 生成时新消息不会自动触发请求，面板提示「有新消息，点此更新建议」。
- 填入只写入原聊天输入框，不点击发送。成功后关闭抽屉，再打开会选中下一条（末条停留），也可重新点选任意条。上一条尚留在输入框时，不能用下一条覆盖，需先发送、清空或撤销。复制不推进选择。原稿保留；撤销成功且仍为同一组建议时回选被撤销条目，重新生成后不会误回退新建议的选择。如果用户已继续编辑或发送，撤销不会覆盖新内容。
- 输入框在等待期间被修改，拒绝覆盖，用户可复制建议或重新打开。切换聊天、离开页面、关闭面板均取消 HTTP；过期结果不能写入其他聊天。
- 关闭只取消未完成请求，不清空已成功结果。进程内保留最近 12 个聊天的最后一组成功回复、理由、生成时上下文、身份、补充想法和选中条目，按聊天隔离；重写失败保留上一组，明确不同重点消息的长按请求不误复用旧结果。不落盘，微信进程结束后清空。
- 切换身份后旧建议标注为上次结果，复制/填入/更简短禁用，需主动按新身份生成；切回原身份可以继续使用。失败或取消时不把旧结果改标成新身份，重开恢复最后成功结果的身份。未生成的身份修改及补充想法不长期保存。

## 上下文与知识

主动生成先从当前页面取得同一聊天的文字锚点，再在 IO 线程复用微信已打开的 WCDB `EnMicroMsg.db`，核对锚点的 ID、时间、发送人及正文，然后按 `talker` 参数查询 `message` 表最近 101 条合格文字（多一条用于判断截取），按时间和 ID 排序后保留最近最多 100 条，文字总量最多 48,000 UTF-16 单位。不依赖手动向上滚动，不遍历联系人，不打开数据库文件、不读取密钥、不写入或关闭微信数据库；不读取已清理或仅存在另一台设备上的记录。

兼容 `com.tencent.wcdb.compat.SQLiteDatabase` 和旧版 `com.tencent.wcdb.database.SQLiteDatabase` 的查询入口，只保留最多四个主库弱引用。表结构及新旧入口依据 [WeKit 数据服务](https://github.com/Ujhhgtg/WeKit/blob/bdc7f18033d87a2f6307d2caedfdc6502986a401/app/src/main/java/dev/ujhhgtg/wekit/features/api/core/WeDatabaseApi.kt)、[查询监听](https://github.com/Ujhhgtg/WeKit/blob/bdc7f18033d87a2f6307d2caedfdc6502986a401/app/src/main/java/dev/ujhhgtg/wekit/features/api/core/WeDatabaseListenerApi.kt)；反射方法签名核对了 [腾讯 WCDB 兼容接口](https://github.com/Tencent/wcdb/blob/39dd797099d41cf1953d5668acd8cb608016c599/src/java/compat/src/main/java/com/tencent/wcdb/compat/SQLiteDatabase.java)。这里是独立实现的只读窄接口，并未接入上游批量修改、发送或导出能力；具体微信版本仍需实机确认。

数据库不可用或锚点不匹配时，退回页面最多 400 个已加载位置里的文字，并显式提示「仅参考页面消息」，模型也收到来源与不完整标记。参考入口展示实际条数、来源、时间范围和原文；历史成功也只代表本机的近期文字，不声称完整聊天。群聊保留成员标识，私聊标为「我 / 对方」。时间缺失显示未知；图片、语音及引用卡片不参与理解。历史查询不统计全部媒体总数，页面回退才报告其已扫描片段的非文字跳过数。不会继承 Jev 的单条 1000 字限制。

回复逻辑与原始知识来自 [狗头军师 goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi)，固定提交 `6db7354a4002dc7c448a9c87ffdad8132570c9d3`。`app/src/main/assets/goutoujunshi/` 保存原始 SKILL、全部 43 份参考 Markdown、MIT LICENSE 和来源记录，合计 44 份规则/知识文档。全部原始资产保留，请求按身份加载 3–5 份：SKILL、话术编排、接话技巧为通用入口，另取恋爱启动、亲密沟通、家庭、情绪回应或表达逻辑资料。上游没有每种身份的独立手册，长辈与弟妹使用已有家庭/沟通资料，身份分寸由言外的明确提示补充，不假称上游存在专属章节。费用与等待时间取决于服务商及聊天长度。

言外覆盖上游桌面工作流：不运行 Python、ChatLab、建档问卷、记忆脚本，不创建长期关系档案。结合原文、所选身份、用户草稿与补充目标，生成 `replies` 字符串数组和 `reason`，兼容旧模型的单条 `reply`。空数组、空白条目、非字符串条目、超量、超长、截断输出均失败，不静默截取或回退成残缺建议。聊天内容作为证据而非指令；Jev 推测不会被自动当成确定事实加入回复。

## 开发边界

- `ReplySettings` 独立配置，通过现有受限 Provider 和签名广播传入微信，只在内存保留副本。
- `ReplyProvider / ReplyProfiles` 提供预设、分账户持久化及旧配置迁移；`ReplyModelsClient` 使用同一 Base URL 下的 `GET /models`、Bearer 鉴权、40 秒总超时、1 MiB 响应上限，禁止重定向转发 Key。过滤明确的非文本模型；未知模型保留给用户检测，不宣称列表中的模型均兼容。
- `ReplyContext` 控制消息数量、总长度、身份及时间；`ReplySession` 阻止取消或替换后的回调落地。
- `ReplyDatabaseHistory / ReplyHistoryReader` 负责宿主查询句柄、同聊天锚点核对、参数化限量查询和透明回退。只有用户生成/重写时查询，重开缓存和定时 UI 检查不查库。查询完成、上传之前再次核对会话、许可、配置及请求状态；取消后不上传结果，游标始终关闭，微信数据库所有权不变。日志仅记录来源、条数及截取标志。
- `ReplyHistory` 为有界进程缓存，仅在生成成功或关闭已成功建议时保存；与取消请求、关闭视图分离。
- `ReplyComposition` 管理身份、成功结果和分条选择，构造和选择都不请求网络；保留生成时的证据，不用当前未提交的身份或想法覆盖旧结果。`ReplyRelationship / ReplyKnowledgeCatalog` 管理身份提示和原始资料路径，`ReplyKnowledge` 按身份缓存只读资料。
- `ReplyProtocol / ReplyHttpClient` 负责提示、响应校验、受限读取、HTTP 超时与取消，不输出密钥或服务商原始错误正文。
- `ReplyHostUi / ReplyTheme` 使用有显式背景、描边、反馈态的宿主原生控件，模块资源只通过模块 Context 读取知识资产。不会在微信 UI 中引用模块资源 ID。`ReplyPlusEntry` 匹配 AppPanel → 单一 LinearLayout → MMFlipper 的结构，包裹原内容并给其剩余高度，保留原 LayoutParams 用于恢复；不依赖混淆资源 ID，不替换原生功能点击。
- `ReplySettingsUi` 管理独立设置页面。撤销同意只影响回复生成，Jev 会话开关不因此变化。

## 手机验收

离线单测与 Debug 构建不能证明微信布局兼容或真实模型回复质量，以下由用户检查：

1. 两个设置页分别配置、切换、保存；六家回复供应商与自定义分别记住 Key 和模型。升级旧配置后切换保存，再切回旧供应商，确认旧 Key/模型仍在。
2. 在回复页获取模型、下拉选择/输入筛选、手动填写；更换 Key 清除旧列表，错误 Key/不支持列表时可修正并重试。GLM/豆包参考目录明确区别于实时列表，选定模型后再检测回复。
3. 私聊和群聊点「＋」，确认顶部出现「帮我回」，原有照片/拍摄/文件及分页仍可用，键盘/表情切换正常；收起后聊天无横条或留白。若未出现，用长按「分析」的备用入口，并反馈实际面板布局。
4. 重启微信后进入已有超过 100 条文字的私聊，不向上翻页，点「帮我回」确认没有自动请求；选身份并点「生成回复」。生成后正常应显示「100 条 · 本机历史」（超长文本可能因总长度限制更少），时间范围应覆盖首屏之前的消息。短聊天应显示实际数量；读取失败必须显示页面来源及原因。私聊/群聊均核对双方、时间、最新内容和长文本，切换聊天不串内容。长按入口不产生引用框。
5. 填入、手动修改、撤销填入、发送后撤销；原稿不被误覆盖。
6. 生成时来新消息，只有点更新才重新请求；关闭或快速切换联系人不会串结果。
7. 超时、错误 Key、短上下文模型、输出不合法时可重试；正常发送始终可用。
8. 分别选择朋友、恋人、长辈、弟妹等身份，以日常、暧昧、冲突、拒绝、告别等真实片段评价口吻与分条自然度；语气词不能模板化。更换身份不自动请求，旧建议需明确标注且暂不可使用；失败或取消不改标旧建议。不能把连通性检测通过等同于效果达标。
9. 生成成功后关闭、重开，回复/理由/补充想法仍在且没有新请求；切换联系人再回来不会串内容。查看旧消息或改为语音输入时仍可重开复制。重写失败、取消重写均保留上一条。
10. 浅深色、大字号、软键盘打开时，身份菜单、输入框与焦点清楚，理由可展开，生成及底部复制/填入可操作。两条以上建议只填选中条；重开选下一条，上一条未发不能覆盖。撤销回选原条后可再填，同一句重复填入后仍能撤销回原稿，生成新一组后撤销旧填入不改新一组选择。最后一条不循环到第一条，复制不推进，不自动发送。
