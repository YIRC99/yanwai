# 帮我回

言外把 Jev 情绪判断和 LLM 回复建议分开。桌面设置页顶部切换「情绪判断 / 回复建议」，两套地址、Key、模型、检测状态独立。只配置回复模型也可以使用「帮我回」。

## 配置

1. 在「回复建议」填写服务商的 OpenAI 兼容 Chat Completions 地址、API Key、模型 ID。
2. 阅读说明，开启「允许手动生成回复建议」，保存。未开启时聊天入口会引导配置，不上传聊天。
3. 「保存并检测回复」使用示例聊天和完整知识库生成一次真实回复，验证接口及输出格式。不会读取微信聊天；该调用使用自己的服务商额度。

根地址自动补 `/v1/chat/completions`，已有路径的 Base URL 补 `/chat/completions`，完整地址不重复追加。地址不允许包含账号密码、查询参数、锚点。使用 Bearer Key、`model`、`messages` 和 `stream=false`，不要求服务商支持专用工具调用或 `response_format`。系统指令要求 JSON 回复；空结果、拒绝、输出被截断、无法解析、HTTP/业务错误均显示失败，不把残缺输出当成可发送建议。

## 聊天流程

- 输入区上方出现「言外 / 帮我回」辅助栏，随输入区移动；在消息列表底部预留空间，离开时恢复。需微信实际布局支持。
- 点「帮我回」时才收集当前聊天，底部展开面板。查看旧聊天时引导先回到底部，避免把旧片段当成当前对话。
- 一条首选回复、折叠的理由、换一句、更简短、补充想法；默认回应当前整段聊天。长按对方文字也可「帮我回」，仅传递重点消息 ID，不启用微信引用回复。
- 点击参考范围可以查看这一次实际带入的消息、说话人及时间。
- 生成时新消息不会自动触发请求，面板提示「有新消息，点此更新建议」。
- 「填入输入框」只写入原聊天输入框，不点击发送。原稿保留，可通过辅助栏「撤销填入」恢复；如果用户已继续编辑或发送，撤销不会覆盖新内容。
- 输入框在等待期间被修改，拒绝覆盖，用户可复制建议或重新打开。切换聊天、离开页面、关闭面板均取消 HTTP；过期结果不能写入其他聊天。

## 上下文与知识

聊天来自当前页面已加载的 adapter，不读取完整数据库。向前最多检查 400 个已加载位置，选择最近最多 100 条双方纯文字，文字总量最多 48,000 UTF-16 单位。群聊保留成员标识；私聊标为「我 / 对方」。时间来自 `field_createTime`，缺失显示未知，不猜测。图片、语音、引用卡片等非纯文本不理解，报告跳过数量。不会继承 Jev 的单条 1000 字限制。

回复逻辑与原始知识来自 [狗头军师 goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi)，固定提交 `6db7354a4002dc7c448a9c87ffdad8132570c9d3`。`app/src/main/assets/goutoujunshi/` 保存原始 SKILL、全部 43 份参考 Markdown、MIT LICENSE 和来源记录，合计 44 份规则/知识文档。完整资料随每次回复请求送入模型，适合长上下文模型，费用与等待时间取决于所选服务商。用户可在设置页阅读归属和完整许可证。

言外覆盖上游桌面工作流：不运行 Python、ChatLab、建档问卷、记忆脚本，不创建长期关系档案。保留回复原则和知识，要求先考虑原文、用户草稿与补充目标，最终生成 `reply` 和 `reason`。聊天内容作为证据而非指令；Jev 推测不会被自动当成确定事实加入回复。

## 开发边界

- `ReplySettings` 独立配置，通过现有受限 Provider 和签名广播传入微信，只在内存保留副本。
- `ReplyContext` 控制消息数量、总长度、身份及时间；`ReplySession` 阻止取消或替换后的回调落地。
- `ReplyProtocol / ReplyHttpClient` 负责提示、响应校验、受限读取、HTTP 超时与取消，不输出密钥或服务商原始错误正文。
- `ReplyHostUi` 使用宿主原生控件，模块资源只通过模块 Context 读取知识资产。不会在微信 UI 中引用模块资源 ID。
- `ReplySettingsUi` 管理独立设置页面。撤销同意只影响回复生成，Jev 会话开关不因此变化。

## 手机验收

离线单测与 Debug 构建不能证明微信布局兼容或真实模型回复质量，以下由用户检查：

1. 两个设置页分别配置、切换、保存；Key 不串用，未保存提示、检测成功/失败清晰；只设置回复模型也可使用。
2. 私聊底部、键盘打开/收起、浅深色时辅助栏不挡消息和输入。上滑看旧聊天再点击，提示回到底部。
3. 连续收几条消息再生成，参考范围包含双方、时间、最新内容和长文本。长按入口不产生引用框。
4. 填入、手动修改、撤销填入、发送后撤销；原稿不被误覆盖。
5. 生成时来新消息，只有点更新才重新请求；关闭或快速切换联系人不会串结果。
6. 超时、错误 Key、短上下文模型、输出不合法时可重试；正常发送始终可用。
7. 用日常、暧昧、冲突、拒绝、对方告别等真实片段评价回复自然度，不能把连通性检测通过等同于效果达标。
