# 2.0.0 语音支持

## 使用

- 开启当前聊天的分析开关：对方当前可见的语音自动转写，再显示情绪和意图分析；分析卡同时展示转写文字。
- 长按对方语音「翻译意图」：只分析该条，不打开自动分析。长按「帮我回」同样可以把语音设为关注点。
- 分析前文：保留目标之前双方的文字和语音，最多扫描 80 个页面位置、保留 24 条，转写后总长最多 12000 字符。不会取目标之后的消息。
- 回复和找话题：最近 30/50/100 条按文字与语音合计，包含自己的语音和屏幕外的本机历史语音。准备上下文时显示语音转写进度，准备完成后再允许生成。可在「查看已读取」和「查看依据」看到原发送人、时间、转写正文及失败缺口。
- 转写失败时：目标语音不发起情绪分析；前文或回复上下文保留“语音未能转写，内容未知”，其他可用文字仍可使用。全部语音失败且没有文字时禁止生成。分析失败卡可点击重试，回复可通过条数菜单重新读取。

语音转写不是声学情绪识别。提示词明确标注转写来源与识别误差，不根据不存在的音调、哭腔、语速信息推断情绪。

## 原生接入

`NativeVoiceBridge` 使用 DexKit 的字符串特征定位微信 `TransformComponent` 和聊天上下文，按方法签名及枚举状态核对转写入口；不硬编码混淆类名。反射签名缺失或存在歧义时，显示未适配，不猜方法。

`ReplyDatabaseHistory` 继续复用微信已打开的 `EnMicroMsg.db`。历史查询纳入 type 1 与 34；语音逐条按会话、消息 ID、时间、方向、文件标识和服务端 ID 验证，使用微信 `convertFrom(Cursor)` 还原完整消息对象，不自己拼接缺少媒体字段的对象。转写前优先读取同一个已验证数据库的 `VoiceTransText`，按 msgId 与 cmsgId 匹配；文件标识和宿主对象不会发给模型。

自动分析和回复共用串行转写入口。已存在的微信转写任务等待完成，不重复点击或关闭它；已有结果由微信转写表复用，不额外在模块磁盘保存正文。没有已有结果时调用原生转写方法，并等待完成状态，单条最多等待 30 秒。微信原生流程可能联网并写入自己的转写状态与结果；模块不直接修改微信数据库、不自动播放语音、不额外调用标记已播放接口。

每次调用及等待期间检查当前聊天与功能许可。离开页面、关闭分析或取消回复准备时，取消本次等待和后续模型调用；已经交给微信的原生请求由微信管理，不强行取消可能由用户或其他功能共同使用的任务。迟到结果不会显示到其他消息。

尚未下载、已清理、已撤回、语言不受支持、网络失败、原生接口变化都可能导致失败；不承诺恢复本机已不存在的音频。

## 验证与来源

- 参考 [WeKit AutoSpeechToText](https://github.com/Ujhhgtg/WeKit/blob/bdc7f18033d87a2f6307d2caedfdc6502986a401/app/src/main/java/dev/ujhhgtg/wekit/features/items/chat/AutoSpeechToText.kt) 的原生转写入口思路，本项目独立实现消息身份核验、历史加载、等待和模型输入准备。
- 对连接手机的微信 **8.0.71 / versionCode 3080** 安装包做了只读字节码核对：确认转写方法 `(MsgInfo, boolean, int, int)`、按消息 ID 的状态查询、`(long, String) -> String` 结果读取、`VoiceTransText` 的 `msgId/cmsgId/content`、聊天标识获取及语音 ViewHolder 的 `getMainContainerView()`。
- 这是安装包静态核对，不等于真实语音转写端到端验证。离线测试验证筛选、历史条数、转写准备、失败与取消、协议保护和反射签名选择。Debug 构建及最终测试结果见本次提交记录。

## 手机验收

1. 重启微信，进入有新语音的私聊，开启分析；应先转写，再在语音下显示分析和正文。关闭开关应停止新分析。
2. 关闭自动分析，长按语音「翻译意图」；只出现该条结果，长按「帮我回」可正常打开回复。
3. 群聊及私聊里混合双方文字和语音，打开「帮我回」，切换 30/50/100；包含屏幕外语音，时间顺序、发送人和实际数量正确。查看依据后生成回复和话题。
4. 重复参考同一条语音复用已有转写；未能转写时明确提示，全部失败不生成；通过菜单重新读取可重试。
5. 转写途中切换聊天、关闭面板或关闭分析，旧结果不串到新聊天；检查长语音、弱网及气泡高度，原播放、长按菜单和未播放红点行为是否符合预期。
