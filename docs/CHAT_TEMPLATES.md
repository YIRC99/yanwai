# 闲聊分析卡（0.5.0）

模板入口：`app/src/main/java/dev/jev/wechatmood/analysis/ChatTemplates.kt`。

## 场景库

| 场景 | 4 个分析角度 |
| --- | --- |
| 日常分享 daily | 分享经历、分享成就、吐槽或求办法、延续话题 |
| 邀约安排 invite | 试探邀约、具体安排、婉拒或时间不合适、确认安排 |
| 关心靠近 care | 关心近况、寻求陪伴、相互了解、确认被重视 |
| 玩笑试探 tease | 友好玩笑、试探态度、接受夸奖、停止不舒服的玩笑 |
| 约定记忆 promise | 重视还是记忆、核对具体内容、约定进展、下一步行动 |
| 委屈不满 friction | 倾听感受、尊重暂停、识别明确边界、避免过度解读短句 |
| 解释修复 repair | 对齐问题、具体道歉、补救行动、接受后收尾 |
| 缓和收尾 closing | 气氛缓和、晚安告别、确认完成、自然停顿 |

## 一条卡片如何产生

1. 第一轮 Jev 从原消息及前文判断 `scene`、`emotion`、`warmth`、`progress`。工作事务、不适用、信息不足有独立选项。
2. 代码按场景和对话阶段过滤模板。等待行动时停止部分反复解释的卡片；已经接受或收尾时停止道歉、追问类卡片。
3. 第二轮把第一轮结果作为**可能出错的估计**，同时保留聊天原文。`focus` 选择最相关问题或 none，各模板的 `reading_*` 独立判断，`evidence` 只从提供的原话中选择参考。
4. 每个问题有 `signal`（该模板提出的解释）、`ordinary`（另一种普通解释）、`unclear`（信息不足/不适用）。不能把 signal 当成默认正确答案。
5. 代码用被选问题的答案决定标题及动作；ordinary 不沿用 signal 的戏剧化标题或建议。原话只展示选中的实际消息，注明当前/前文及说话方，长句缩略。
6. 第一层路由不明确则只调用一次；第二层选择 none、不明确或信息不足则显示「先别急着猜」。完整返回但信心不足属于正常结果，接口失败/返回缺字段属于可重试失败，两者不能混淆。

当前展示门槛是选项概率至少 0.55 且 confidence 至少 0.35，属于初始产品参数，尚未通过闲聊样本校准。卡片概率是模型对备选解释的估计，不是恋爱概率或事实发生频率。

## 添加和调整模板

每个 `ChatTemplate` 包含唯一 id、scene、标题、问题、两个竞争解释、各自对应动作，以及 `onlyDuring`（适用阶段）和 `stopDuring`（停止阶段）。默认在 accepted / closing 时停止；收尾类显式保留。阶段判断本身不明确时不过早排除候选。

先用具体误判样例调整问题、竞争解释和阶段条件，避免只靠增加同义话术。动作应该具体且可执行，不包含操控、欺骗、制造嫉妒或逼迫对方回应的套路。每套都保留正常解释和信息不足的出口。

离线测试使用人工构造的 Jev 响应，验证路由、两轮传递、停止条件、文案分支和协议校验。它们不能验证真实模型是否理解了聊天；用户实聊验收时重点关注是否贴合、是否重复、是否误判、展示长度和响应等待时间。
